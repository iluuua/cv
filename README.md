## Опыт

### ReachFlow, Founder

Январь 2026 по настоящее время.

Основал [ReachFlow](https://reachflow.tech), B2B SaaS для поиска клиентов и автоматизации продаж в Telegram. Разрабатываю backend на FastAPI и PostgreSQL, интеграции с Telegram и LLM, фоновые процессы и инфраструктуру развёртывания.

На Linux VPS запускаю API, шлюз и воркеры в отдельных Docker-контейнерах через Compose. Автоматизировал выпуск обновлений через GitHub webhooks и systemd: проверки перед релизом, резервная копия PostgreSQL, пробное восстановление и миграции на отдельной базе, проверка версии и здоровья сервисов после запуска, откат при сбое. Разбирал зависания webhook receiver и потерю событий при одновременных обновлениях.

Для проверок кода использую GitHub Actions, pytest и ruff. Диагностика опирается на health endpoints, структурированные логи, request-id и trace-id. Работал с DNS, TLS, Caddy/nginx и CDN; проверял HTTP/2, передачу POST-запросов и потоковых ответов. Есть базовый опыт работы с Kubernetes-манифестами для воркеров.

В LLM-слое реализовал классификацию состояния диалога, извлечение фактов, память агента и вызовы инструментов. Ответы проверяются по строгим JSON-схемам; ошибки обрабатываются повторными запросами и резервными провайдерами. Каждая попытка записывается с моделью, временем ответа и стоимостью.

Объединил пять классификаторных вызовов в два. В измеренных сценариях объём входных символов сократился на 14% для короткого диалога, на 38% для типового и на 43% для длинного. Невалидная секция ответа получает статус `unanswered` и не влияет на остальные секции.

Для чтения сайтов написал отдельный сервис на FastAPI, Playwright и Chromium. Его вынес в отдельный процесс после замера пика памяти в 413 МБ при лимите 1 ГБ. Содержимое проходит проверку качества и защиту от SSRF. В контекст модели передаётся карточка из шести полей с выдержкой до 1200 символов.

Разобрал случай, когда семантический фильтр на эмбеддингах отбраковывал 55 кандидатов из 63 из-за формата и длины текста. Перевёл его в режим наблюдения; решение о релевантности оставил за LLM-квалификацией с машиночитаемой причиной отказа.

## Проекты и соревнования

### Обнаружение препятствий для Московского метрополитена

[Решение команды xixi-square](https://github.com/iluuua/subway-obstacles-detection), задача №5 конкурса «Лидеры цифровой трансформации 2026».

Капитан команды; отвечал за алгоритм и интеграцию с ROS 2 Humble. Детектор находит препятствия в облаках точек 3D-лидара. Последний кадр обрабатывается в отдельном процессе, чтобы при перегрузке не накапливалась очередь. Решение упаковано в Docker. На синтетике организаторов обнаружены все 8 препятствий; на проверенных 15,7 км реальных записей ложных тревог не было.

### Финалист AIDAO 2025

Международная олимпиада по ИИ и анализу данных, Яндекс Образование и ФКН НИУ ВШЭ. Топ-30 команд из 248 из 14 стран; очный финал с 28 по 30 ноября 2025, 32 часа решения.

Для задачи команды беспилотных технологий Яндекса реализовал [Lift-Splat-Shoot на PyTorch](https://github.com/iluuua/aidao-2025-bev-occupancy): occupancy-карта в bird's-eye view по четырём камерам автомобиля. IoU на закрытом тесте составил 0.5606, у команды-победителя 0.564.
