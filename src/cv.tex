\section{Опыт работы}

\role{ReachFlow, ML/NLP и backend инженер}{с января 2026}
\textit{B2B SaaS, ИИ-ассистент, который ведёт продающие переписки в Telegram \textperiodcentered{} \href{https://reachflow.tech}{reachflow.tech}}

\textbf{Конвейер диалога.} На входящее сообщение уходит шесть-семь вызовов модели. Гейт решает, дозрел ли ход,
классификатор размечает состояние лида по 16 типам событий, факты извлекаются и взвешиваются по 18 ключам,
затем ответ пишет стратег, переписывает писатель и проверяет ревьюер. Два вызова условные, они пропускаются,
когда взвешивать нечего и проверять нечего. Реестр держит 25 задач, 22 строгие схемы на pydantic
и 43 инструмента агента, из которых 10 помечены опасными.

\textbf{Удешевление хода.} Раньше уходило десять-одиннадцать вызовов. Я слил пять классификаторных обращений
в два, потому что одна модель отдаёт несколько секций одним объектом, и это убрало дублирование истории диалога
в промптах. Экономия входных символов вышла 14 процентов на коротком ходе, 38 на типовом и 43 на тяжёлом треде.

\textbf{Чтение сайтов в контекст.} Написал агента, который забирает страницу по ссылке из переписки прямо
в контекст диалога, и отдельный сервис рендеринга на Playwright и Chromium под него. Каскад из четырёх ступеней
останавливается по порогу качества, а не на первом успехе, иначе заглушка Cloudflare уехала бы в промпт как
содержимое сайта. В модель идёт типизированная карточка из шести полей с выдержкой в 1200 символов, это граница
доверия против инъекций со стороннего ресурса.

\textbf{Организация контекста.} Под бюджет промпта контекст деградирует ступенями, а не режется по длине:
списки укорачиваются по кругу, и только затем выбрасываются поля по таблице из 44 приоритетов. Запреты выведены
из ранжирования по репликам лида, иначе случайная фраза вымывала бы из промпта нужный запрет.

\section{ML-проекты и соревнования}

\role{AIDAO, Олимпиада по искусственному интеллекту и анализу данных}{2025}
\textit{Яндекс Образование и факультет компьютерных наук НИУ ВШЭ. Финалист, очный финал с 28 по 30 ноября 2025,
32 часа, топ-30 команд из 248 заявок от участников из 14 стран. Задачу ставила команда беспилотных технологий
Яндекса, нужно было построить occupancy-карту в bird's-eye view по камерам автомобиля со скором по IoU.
Решение с нуля на PyTorch, репозиторий \texttt{aidao-2025-bev-occupancy}.}
\begin{itemize}
  \item Реализовал \textbf{Lift-Splat-Shoot}. Общий для камер ResNet-50 сливает уровни /8 и /16 через FPN,
        depth-head раскладывает глубину на 64 бина с обучаемой температурой softmax, признаки дифференцируемо
        разлетаются в BEV-сетку 188$\times$126. Камеры сливаются через max и mean с SE-блоком, декодер на dilated
        residual-блоках.
  \item Главный прирост дала \textbf{покадровая калибровка} вместо фиксированной. Геометрия проекции пересчитывается
        на каждом кадре из \textit{intrinsics} и \textit{car\_to\_cam}, а сетка пикселей переносится в координаты
        исходного изображения, потому что у четырёх камер разные разрешения.
  \item Лосс собрал из BCE с \texttt{pos\_weight} по балансу классов и $0.3\times$ дифференцируемого surrogate mIoU,
        то есть оптимизировал ту метрику, по которой считался скор. Учил AdamW с раздельными lr для backbone
        и голов, с cosine annealing и AMP, порог калибровал свипом по валидации.
  \item На скрытом тесте вышло \textbf{IoU 0.5606}, у команды-победителя олимпиады 0.564. Инференс 2000 кадров
        занимает 1,7 минуты на одной GPU.
\end{itemize}
